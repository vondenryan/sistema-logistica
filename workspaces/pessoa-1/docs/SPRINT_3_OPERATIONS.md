# Verificação isolada Sprint 3

Em `workspaces/pessoa-1`, execute `scripts/verify-sprint3.sh`. Requisitos: Docker acessível, imagem `postgres:16` já em cache, Java 21, Python 3 e cache Maven completo em `backend/.cache`. O build usa cópia privada da árvore backend e do cache com Maven `-o`, sem limpar ou modificar `target` compartilhado. Imagem usa `--pull never`. Falta de cache falha sem download. O verificador não executa testes Maven nem frontend; execute as suítes responsáveis separadamente.

Um diretório temporário privado guarda build, cópia do cache e logs; um container novo e volume anônimo pertencem apenas à execução. PostgreSQL escuta porta aleatória em 127.0.0.1; usuário, senha, JWT e senha demo são gerados para a execução, sem `.env`, credenciais remotas ou banco existente. A aplicação recebe ambiente filtrado, perfil dev, roteamento fake e tarifa `2.50` **somente como fixture de teste**. Os logs são privados e apagados, nunca arquivados ou impressos; falhas de build/startup são reportadas sem despejar logs. Saída contém apenas resultados sanitizados. O processo Java e container identificados pela execução são encerrados no cleanup, que remove também o volume anônimo e diretório temporário. Interrupção forçada (SIGKILL ou perda do host) pode exigir remoção manual do container criado.

O script aguarda `pg_isready` e login efetivo após o seed, com prazos limitados. Testa 401, 403 e 400 com ProblemDetail, fluxo de dois pedidos, confirmação repetida, cotações repetidas, sugestão/reordenação, atribuição repetida e início; então confere contagens persistidas no PostgreSQL descartável. A porta HTTP escolhida pode sofrer corrida de bind; nesse caso a execução falha e pode ser repetida. É um teste dos fakes e P1 local, não da integração P2/P3. A aplicação usa fake em processo e nenhum endpoint externo é configurado; Maven offline e imagem em cache evitam downloads. Isso não é bloqueio de rede em nível de pacote.

Teste independente do cliente contra stub HTTP local: `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s contract-tests -p test_smoke_sprint3.py -v`. O stub verifica validação de erros do cliente e não substitui a execução do backend/PostgreSQL. Sintaxe shell: `bash -n scripts/verify-sprint3.sh`. Browser e E2E com serviços reais são verificados separadamente pelo responsável principal.
