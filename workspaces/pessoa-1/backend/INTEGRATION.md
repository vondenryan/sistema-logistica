# Integration handoff

The workspace-local `contracts.v1` package contains canonical ports and DTOs; root contracts are unchanged. Identity provides `CurrentActorPort`, orders provides `OrderSnapshotPort`, and routing provides `RouteSnapshotPort`. Billing exposes a local freight lookup port to orders; consumers do not query billing tables. Replace dev/test `Fixtures` with Pessoa 2 and 3 implementations of partner, fleet, delivery, notification and document ports. Calls use Java ports, not cross-module SQL or HTTP.

Confirmation and assignment persist local reconciliation state and use stable event IDs. Assignment can return 503 after the fleet reservation succeeds; retry the same route, or allow the scheduled retry to finish. Start is blocked while delivery assignment remains pending. The delivery contract has no command to transition deliveries to in-transit on route start; that transition remains Pessoa 3's responsibility until the shared contract is extended through the agreed process.

The dev-only replay first rebuilds confirmation fakes, then restores fake fleet and deliveries for assigned and in-progress routes. These in-memory fakes are not durable real fleet or delivery implementations. The fake has one driver/vehicle and refuses multiple active reservations. Route stops currently have an unconditional order uniqueness constraint: route completion/cancellation and releasing that constraint for a terminal route remain future lifecycle work.

Flyway migrations V5 and V6 extend V1–V4 without changing them; coordinate global version allocation before shared integration. Freight tariff and geocoding provider remain deployment/business decisions. Set `FREIGHT_TARIFF_PER_KM` explicitly for new quotes; confirmed order quotes are immutable and remain readable without configuration or OSRM. `ROUTING_PROVIDER=fake` is dev/test only, while OSRM is the default. See README for runtime settings and the offline test command. No P2/P3 business implementation is supplied here.
